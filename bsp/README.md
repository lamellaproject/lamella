# Board support

Each board has one folder under `boards/`, named by the board's id, the name a build selects the
board by: `boards/rpi-pico2/` is the Raspberry Pi Pico 2. A board's folder holds:

- `board.toml`, the board's facts and the documents they come from.
- `csharp/`, the board's C# package: its bindings and, on most boards, the board class that binds
  the board's buses to its chip's drivers. `csharp/build-boards.ps1` compiles the package into the board's
  facts assembly, `boards/<board-id>/Lamella.Hardware.Facts.dll`. Every type in the package is internal
  to that assembly, as are its chip family's: a program reaches the board through
  `Lamella.Hardware.TargetBoard` and the `System.Device` types.
- `rust/`, `python/` and, on some boards, `swift/`: the board's bindings in those languages.

A file whose first line says `GENERATED by lamella-bsp-gen` is generated from `board.toml` and the
facts of the board's chip family under `csp/`. Change the facts and regenerate the family, from the
repository's root, rather than editing the file:

```
cargo run -p lamella-bsp-gen -- gen-family . <family>
```

`common/` holds the sources every board compiles, one folder per language. `csharp/build-boards.ps1`
compiles every source under `common/csharp/` into every board's facts assembly.

`Lamella.Hardware.TargetBoard` is compiled once, in `libs/Lamella.Hardware`, against the one name
every board's facts assembly has, `Lamella.Hardware.Facts`. It asks the facts which board the program
was built for through each board's generated `TargetBoardFacts.g.cs`, and a build for a board takes
that board's facts in place of the boardless ones in `libs/Lamella.Hardware.Facts`.
